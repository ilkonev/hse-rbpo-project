# Требования безопасности

| ID | Требование | Критерий приёмки | Связанные T / D |
| --- | --- | --- | --- |
| SR-01 | Чтобы работать с секретами и правами доступа, пользователь должен войти в систему. | Пользователь без входа пытается посмотреть, создать, изменить или удалить секрет либо изменить права доступа. Сервис отказывает, а данные не меняются. | T-04 |
| SR-02 | Пользователь не может видеть или менять данные другого рабочего пространства. | Пользователь из пространства A подставляет идентификатор пространства или секрета из пространства B. Сервис отказывает, не возвращает секрет и не меняет данные пространства B. | T-01 |
| SR-03 | После отзыва доступа пользователь больше не может посмотреть секрет. | Владелец выдаёт читателю доступ к секрету, затем отзывает его. Следующий запрос читателя получает отказ и не содержит значение секрета. | T-03 |
| SR-04 | Владелец может создавать, менять и удалять секреты своего пространства. Редактор может менять только разрешённые ему секреты. Читатель не может создавать, менять или удалять секреты. | Читатель пытается создать, изменить или удалить секрет, а редактор — изменить секрет без права редактирования. Сервис отказывает, а данные не меняются. | T-01, T-05 |
| SR-05 | Выдавать и отзывать доступ к секрету может только владелец рабочего пространства. | Читатель или редактор пытается выдать либо отозвать доступ. Сервис отказывает, а список пользователей с доступом не меняется. | T-02 |
| SR-06 | Пароли пользователей нельзя хранить и показывать в открытом виде. | После регистрации в базе хранится не сам пароль. Пароль не попадает в ответы API и журнал операций. | T-06 |
| SR-07 | Сервис записывает в журнал действия с секретами и правами доступа, но не записывает сами секреты и пароли. | После создания, просмотра, изменения или удаления секрета, а также выдачи или отзыва доступа появляется запись с действием, временем, пользователем и идентификатором объекта. В записи нет значения секрета и пароля. | T-07 |
